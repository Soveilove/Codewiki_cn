# 增量更新

`codewiki generate --update` 会对比上次保存的依赖图，只更新受代码变化影响的文档。默认产物目录是 `<仓库>/.codewiki/`。

```bash
cd /path/to/your/repository
codewiki generate            # 首次生成
# 修改并提交代码
codewiki generate --update   # 更新文档
```

旧的 `docs/` 目录不会自动搬迁。此前把产物写到 `docs/` 的仓库，请继续明确指定目录：

```bash
codewiki generate --output docs --update
```

## 增量更新需要的文件

完整生成后，CodeWiki 会在输出目录保存模块结构、文档、依赖图和元数据。`--update` 使用这些文件判断哪些页面需要修改。

| 文件 | 用途 |
| --- | --- |
| `module_tree.json` | 模块结构以及各叶子模块对应的组件 |
| `<module>.md`、`overview.md` | 模块页面和文档总览 |
| `temp/dependency_graphs/*.json` | 上次生成时保存的依赖图 |
| `temp/artifact_index.json` | 构建和配置类文件索引 |
| `metadata.json` | 生成信息和 Git 提交记录 |

## 更新过程

变更判断以组件为单位，例如类、函数或构建目标；更新任务则按叶子模块组织。CodeWiki 会载入上次依赖图、分析当前代码，再比较组件是否新增、删除、修改或重命名。随后修复模块结构、为受影响的叶子模块生成变更说明，并决定做增量更新还是全量生成。

模型会读取变更说明和当前页面，选择局部修改、重写或保持不变。需要更新父页面时也会纳入处理。未受影响的页面不会被写入。更新结束后，CodeWiki 会检查遗漏页面和过期链接，并保存新的依赖图、模块结构及更新记录。

## 什么时候改为全量生成

运行 Agent 之前会检查受影响范围。如果活跃叶子模块占比或模块结构变化占比超过阈值，CodeWiki 会改为全量生成，并在更新记录中写明原因。已有依赖图无法读取时也会全量生成。

| 判断项目 | 默认阈值 | 参数 |
| --- | --- | --- |
| 受影响叶子模块 / 全部叶子模块 | `0.5` | `--tau-full` |
| 新增、删除或重新聚类的模块 / 全部叶子模块 | `0.3` | `--tau-tree` |

## 指定比较基准

默认使用 `metadata.json` 保存的提交记录作为 Git 比较基准。CI 中或提交历史被压缩后，可以指定仍可访问的基准提交：

```bash
codewiki generate --compare-to <commit-hash>
```

该参数会同时启用 `--update`。如果无法通过 Git 比较，更新器会比较保存的依赖图和当前依赖图。

## 更新参数

日常使用通常只需要 `--update`。其他选项用于调节组件识别和更新范围：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--tau-ren` | `0.95` | 判断删除和新增是否属于重命名的正文相似度阈值 |
| `--tau-nb` | `0.5` | 根据依赖邻居把新组件分配到模块所需的占比 |
| `--tau-grow` | `0.33` | 新组件增长到此占比时，重新聚类父模块 |
| `--tau-full` | `0.5` | 触发全量生成的受影响模块占比 |
| `--tau-tree` | `0.3` | 触发全量生成的模块结构变化占比 |
| `--k-hop` | `1` | 收集上游接口变化时追踪的依赖层数 |
| `--max-diff-tokens` | `8000` | 单个组件变更说明的 token 上限 |

### 更新档位

`--update-rung` 用于选择更新流程。通常保持默认的 `3` 即可。

| 档位 | 行为 |
| --- | --- |
| `0` | 旧版文件级更新：文件有变化时，重建包含该文件组件的模块页面 |
| `1` | 比较依赖图并按规则修复模块结构，重写命中的页面 |
| `2` | 在档位 1 上增加新组件路由、模块扩展处理和相关页面更新 |
| `3`（默认） | 完整组件级流程，允许 Agent 原地修改叶子页面 |
| `3b` | 与档位 3 相同，但额外追踪两层依赖 |

## 更新记录

每次更新都会写入 `<输出目录>/update_record.json`，并把摘要合并到 `metadata.json`。记录包括更新结果、组件变化统计、模块路由决定、回退原因、页面处理结论以及模型调用耗时和 token 数。

`prompt_asset_change` 记录团队约定的检测状态（`no_baseline`、`unchanged`、`changed`）、旧指纹 `stored`、当前指纹 `current`、用户选择 `action`（`ok`、`declined`、`full`）和实际执行方式 `execution`。即使代码无变化而提前退出，也会保存本次 `no_change` 记录。用户选择继续增量后仍可能因代码改动或缺失依赖图而自动转全量，因此 `action` 和 `execution` 分开记录；全量备份位置见 `metadata.json` 的 `last_update.previous_docs`。

## 更新成本示例

在约 12.5 万行 JavaScript 的 svelte 仓库上，使用同一模型测得：

| 运行方式 | 费用 | 时间 |
| --- | ---: | ---: |
| 全量生成 | $21.48 | 2 小时 46 分钟 |
| 一次提交后的增量更新 | $0.34 | 3 分钟 |
